樱花主题天然容易滑向「装饰堆叠」。第一版就有 10 个常驻 `infinite` 动画：飘动的渐变天空、闪烁的星点、三朵漂移的云、摆动的图标、流动的按钮渐变。

在本地打开就觉得不跟手。于是测了一下，不靠感觉。

## 先做开关对照

逐个关掉可疑项，同一路由、同一测量口径跑一遍：

| 变体 | 主线程耗时 | 样式重算 | p95 帧 |
|---|---|---|---|
| 全部开启（10 个动画） | 362.8 ms | 57.2 ms | 11.4 ms |
| 只关 `backdrop-filter` | 355.1 ms | 51.7 ms | 11.5 ms |
| 只关 canvas 花瓣 | 336.8 ms | 58.3 ms | 9.0 ms |
| 只关常驻动画 | **170.4 ms** | **8.0 ms** | **7.5 ms** |

结论有点反直觉：毛玻璃背景只占 2%，**真正贵的是那堆常驻动画**。

## 为什么 `background-position` 特别贵

`sky-drift` 和 `grad-flow` 动的是 `background-position`：

```css
.backdrop__sky {
  background: var(--grad-sky);
  background-size: 200% 200%;
  animation: sky-drift 30s ease-in-out infinite alternate;
}
```

`transform` 和 `opacity` 可以交给合成线程，改 `background-position` 不行——它必须回主线程重新栅格化那一整块渐变。天空是整屏的，按钮和页脚也是大块渐变，等于每帧都在重画半个屏幕。

星点的 `twinkle` 同理：一个整屏元素在持续改 `opacity`，也会让整层反复合成。

## 改成什么样

- 删掉三个 `background-position` / 整屏 `opacity` 动画，改静态渐变与静态星点
- 花瓣降到 30fps（低端设备 24fps），DPR 上限 1.5，数量从 36 降到 26
- 云从三朵减到两朵，只留 `transform` 位移——这个能上合成层，便宜
- 入场动画从 550ms + 位移改成 150ms 纯淡入（位移本身会额外触发合成）
- `body` 上重复的固定渐变背景去掉，交给背景层统一画

## 结果

| 指标 | 之前 | 之后 |
|---|---|---|
| 主线程耗时 | 362.8 ms | 120.4 ms |
| 样式重算 | 57.2 ms | 19.7 ms |
| 最长帧 | 69.9 ms | 24.2 ms |
| 掉帧（>33ms） | 1 | 0 |
| 常驻动画 | 10 | 3 |

视觉上几乎看不出差别——天空还是那个渐变，星星还在，花瓣照旧在飘。省下来的是每帧的绘制量。

> 判断标准不是「这个效果好不好看」，而是「这一帧值不值这个开销」。能上合成层的留，逼着主线程重绘的删。
