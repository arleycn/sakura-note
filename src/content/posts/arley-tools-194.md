首页搜索框下面有一行小字，194 个工具，8 个分类，0 次上传。

前两个数字是数出来的，第三个是设计出来的。tools.arley.cn 里所有工具都在浏览器本地跑完，你拖进去的图片、粘进去的 JSON、填进去的密钥，一个字节都不出这台机器。

地址是 <https://tools.arley.cn>。

## 为什么要做工具站

我手上已经有一个导航站，干的是「把别人的工具指给你」。用久了会发现指过去十个站，八个在弹窗，五个要登录，三个传完文件告诉你「排队中，前面还有 2000 人」。

删掉这些，日常会用到的功能就那么几个。图片压一下、JSON 格式化、时间戳转一下、二维码生成一个、两段文本比比哪里不一样。

这些事浏览器自己就能干。Canvas 能压图，Web Crypto 能加密，CompressionStream 能 gzip，Intl 能算农历，File API 连本地文件都不需要经过网络。既然机器上什么都有，何必把文件传上去排队。

所以这站的第一条规矩定得很早，能在浏览器本地完成的，不许联网。

第二条规矩是分类顺序。二次元和图像排在最前，通用的开发、计算往后放。这站最早是给自己用的，我看动画、玩梗、需要颜文字和抽卡概率，就把这些排在了首页第一屏。市面上的常用工具做底子，全量铺在后面。

## 194 个工具是怎么摆的

每个工具一个目录，两个文件。`index.tsx` 是界面，`logic.ts` 是纯函数。

界面只负责取值、调用、显示，算数全在 `logic.ts` 里，不碰 DOM。这个拆法不是为了目录好看，是因为 `logic.ts` 能被 Node 直接 import 进来跑断言。194 个工具里，凡是值得算的东西，都能在没有浏览器的情况下验证。

命名是硬约束，目录是 `src/tools/<分类>/<别名>/`，slug 就必须等于 `分类-别名`，对不上 `check:tools` 直接退出，构建起不来。这条约束挡掉的是最烦的一类问题，注册表里有一行、目录里没有，或者反过来，页面 404 半天才发现是名字打错了。

现在 8 个分类，编码 37 个、开发 36 个、图像 26 个、文本 24 个、办公 20 个、计算 19 个、生活 19 个、二次元 13 个。

这个分类表是改过的。最早只有六个分类，生活向和办公向的工具全塞在别的分类里，「今天吃什么」挂在二次元下，我自己看着都想笑。后来单独拆了生活和办公两个分类，迁了 14 个工具过去，slug 和目录一起改名。

加一个工具要走的还是那六步，建目录、写 `logic.ts`、写 `tests/<别名>.test.mjs`、在 `tools.json` 登记、给冒烟脚本加一条用例，然后全套检查跑绿。走到第六步还没结束的话，那就是没做完。

页面不是 SPA 空壳。构建的时候会把每个工具的地址预生成成真实 HTML，`/t/<slug>/` 和 `/c/<id>/` 都有自己的标题、描述和 canonical，sitemap 里 204 条全是能直接打开的地址。分享出去一个工具链接，对方看到的不是先白屏再渲染，源文件里就有内容。

工具本身是懒加载的，194 个各打一个分包，二到七 KB，点开哪个下哪个。首屏不为了那 190 个用不上的工具多背一份包。

## 那台自己写的二维码

生成二维码的库很多，npm 装一个最省事。这套编码器是我自己写的，464 行逻辑加 166 行码表。

理由有两个。一是这功能太适合验证了，一个编码器写得对不对，拿个解码器读一遍就知道，不需要截图比对，也不需要肉眼看。二是它足够独立，纠错级别、掩码、版本、码字排布全在纯函数里，不进 DOM。

所以验证脚本干的事很笨。自己编码，自己渲染成像素，交给 jsQR 解回来，和原文逐字比对。40 组样本，中文、长链接、不同纠错级别都塞了，全部原样回来。

<img src="/pic/tools-qr.webp" alt="二维码生成页，正文下面标着版本 2、25×25、掩码 2" width="1280" height="844" loading="lazy" decoding="async">

页面上那行「版本 2 · 25×25 · 掩码 2」不是装饰，是这次编码真实选出来的参数。八个掩码挨个打分，挑罚分最低的那个，这是规范要求，也是肉眼看不出来但对扫码成功率有影响的一步。

## 唯一一个要联网的工具

云剪贴板。它天生是服务端的活，这边写进去，那边读出来，没有任何本地实现能替代。

它在这站是个例外，卡片右边挂着橙色「需要联网」角标，全站就这一个。后端是 Worker 加 D1，取一次就删，删除用的是 `DELETE ... RETURNING`，一次原子操作，不会出现两个人同时抢到同一条的情况。

其它 193 个连后端都不用碰。构建出来的产物是纯静态的，没有任何运行时外联。

## 真正花时间的部分

**图片压缩点了没反应。** 压完还是 688KB，一分没少。查下来是默认输出格式写了 `auto`，等于保持原格式，PNG 重新编码一遍还是那么大。改成默认 WebP，同一张图从 690KB 掉到 33.3KB。

**配色工具整页塌成一片空白。** 新加的配色卡用了 `.palette` 这个类名，而命令面板的遮罩层早就占了同一个词，`position: fixed; inset: 0` 直接把按钮拉成了全屏。后来配色卡改名 `.palette-card`，子元素一起改。改名这件事得三处同时搜，CSS 定义、JSX 里的字符串、`cn()` 的参数，漏一处就是「改了没生效」。

**手机端左边字被切掉。** 内容整体贴边，看起来像 padding 没写。其实 `.hero`、`.cat-block` 和 `.wrap` 是同一个元素，一句 `padding: 30px 0 52px` 把容器的左右留白一起清成了 0。桌面 1440 宽有居中留白挡着看不出来，390 一测就露。三处都改成 `padding-block`。

**黄历页的断言第二天就挂。** 冒烟里写了「九月廿九」「立冬」，第二天日期一变全红。后来只断言不变量，日期格式、干支年正则、格子数是 7 的倍数、吉凶等级在这个集合里，具体值放进失败提示里供排查。写死的期望值等于给自己埋了个定时任务。

**站内每一次点击都多绕一跳。** Cloudflare 的静态资源默认 `auto-trailing-slash`，访问 `/t/codec-qr` 会先 308 跳到 `/t/codec-qr/`。所以站内链接、canonical、sitemap、给别处用的那份工具清单，全得输出带尾斜杠的版本，漏一个就是白绕一圈，而且 canonical 和用户实际待的地址还对不上。

**还有一次差点把六张字母表改坏。** 终端里显示一长串数字，看着像被谁改过，我准备动手。用 `charCodeAt` 打了一遍字符码，48 到 57，全对。是终端显示层在骗人，文件字节一直是好的。

## 怎么知道它没坏

两层。逻辑层是 `npm test`，8407 项断言，跑完不到几秒，不需要浏览器。界面层是 `npm run smoke`，用无头 Edge 打开真实页面点一遍，217 项。

界面这层的坑比逻辑层多得多。写断言时踩过最阴的一个是 `check(name, cond, extra)` 只有三个参数，我习惯性用逗号把条件拆成两段，第二段直接被当成 `extra`，第三段模板字符串静默丢弃。那条断言一直是绿的，实际只校验了前半句。

还有一次是 MBTI 那个工具，想验证「全选负面答案会得到 INFP」，我点了最后一个按钮。选项数组是 `['−−','−','○','+','++']`，最后一个是最正面，全 +2 算出来恰好还是初始类型，断言失败我还以为是计分写错了。后来翻 `ANSWER_OPTIONS` 才发现是自己点反了。

所以现在写冒烟有个习惯，`extra` 一律拼实测变量，不用固定文案。失败的时候能一眼看出是哪个分支挂的，而不是先花十分钟怀疑代码。

<img src="/pic/tools-palette.webp" alt="命令面板输了「二维码」，命中生成和解析两个工具" width="1280" height="800" loading="lazy" decoding="async">

顺带说个用起来最顺的地方，`Ctrl + K` 打开命令面板，打两个字就跳到工具，不用回首页翻分类。这功能本来是给键盘用户做的，后来自己用成了主入口。

## 还没做的

- **离线。** 现在是纯静态站，但没做 Service Worker，断网就白屏。要「装上就能用」，还差一层缓存。
- **工具之间不互通。** 图片压缩完想直接转成 Base64，得下载再传回去。做成流水线会好用得多，但那等于重写一遍状态管理。
- **搜同义词不灵。** 搜「图片变小」找不到图片压缩，得搜「压缩」。关键词是手写的，没做同义扩展。

## 最后

<img class="narrow" src="/pic/tools-mobile.webp" alt="手机端首页，顶栏下面是一条横滑的分类条" width="780" height="1688" loading="lazy" decoding="async">

194 个工具听着多，其实每个都很小，2 到 7KB 一个独立分包，打开哪个下哪个。真正的工作量不在写界面，在两件看不见的事上，一是把每个算法抽出来单独验证，二是把「文件不出本机」这条守住。

它现在能做的事很朴素，压个图、转个格式、算个数、查个码。但这些事本来就不该麻烦别人。

有空来用，<https://tools.arley.cn>。
